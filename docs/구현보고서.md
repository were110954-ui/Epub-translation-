# EPUB AI Translator 확장 구현 보고서

기존 저장소에 CBZ→EPUB, 만화 OCR/식자(PDF·CBZ), 편집기를 덧붙였다. 번역 없는 PDF→EPUB 변환은 나중에 빼 냈다. 소설 EPUB 번역은 같은 큐와 엔진을 그대로 쓴다. 원본 파일은 복사만 하고, DRM 해제나 원본 수정은 없다.

## 1. 기존 구조에서 재사용한 것

확인한 스택은 Python 3.12, FastAPI, lxml, SQLite, Pillow다. 기존 테스트는 26개였고, 이번 변경 후에도 그 테스트는 통과한다.

| 기존 코드 | 그대로 쓰는 역할 |
| --- | --- |
| `pipeline.JobManager` | 작업 생성, `start` / `pause` / `resume` / `cancel`, asyncio 게이트, 청크 체크포인트 |
| `db.py` | 작업, 블록, 청크, 번역 캐시, 용어집, 인물, 이벤트 |
| `engines.py` | OpenAI, Gemini, Anthropic, OpenAI 호환, Mock. 키는 메모리 또는 `data/secrets.json` |
| `context.py`, `chunker.py`, `validator.py` | 만화 대사를 블록으로 넣어 같은 프롬프트·검증·용어집 경로로 번역 |
| `qa.py` | 구조 검사, EPUBCheck, JSON/HTML 보고서 |
| `server.py`, `static/index.html` | 같은 화면, 같은 진행률·로그·다운로드·용어집 |
| `cli.py` | `python -m epub_translator translate --src-lang en` 유지 |
| `rebuild.py` | 소설용 한국어 가독성 CSS(`keep-all`)는 수정하지 않음 |
| `start.bat`, `start.sh` | 더블클릭/셸 기동 유지. `start.bat`에는 선택 의존성 안내 한 줄만 추가 |

소설 작업 ID(`job_key`)는 엔진, 모델, 언어, 후리가나 여부만 사용한다. 모드를 해시 식에 넣지 않아서 예전에 만들어진 소설 작업은 같은 ID로 이어진다.

## 2. 최소 확장

파일 매직바이트로 종류를 정한다.

- `.epub` → 기존 소설 번역
- `.cbz` / 이미지 ZIP → EPUB3 고정 레이아웃. 체크하면 만화 모드
- `.pdf` → 번역 없는 변환은 제거됨. 만화 번역을 명시할 때만 받음

이후 변경: PDF를 리더에서 그대로 볼 수 있어 **단독 PDF→EPUB 변환은 UI/API/CLI에서 빼 냈다.** 추출 코드는 만화 번역이 PDF를 받을 때 그대로 쓴다. 옛 `mode=pdf` 행과 결과 파일은 지우지 않고, 완료본 다운로드는 되며 시작·재개는 거부한다.

만화 모드는 PDF/CBZ만 받는다. 소설 EPUB 안의 그림 글자를 OCR하지 않는다.

PDF는 회전이 없고 텍스트 레이어가 없으며 화면에 그려진 JPEG가 하나일 때 스트림 바이트를 그대로 꺼낸다. Pillow로 JPEG을 다시 저장하지 않는다. 그 외 페이지는 PyMuPDF 또는 `pdftoppm`으로 300–600 DPI PNG를 만든다. 렌더러가 없으면 그 페이지만 실패하고, 성공한 페이지 순서는 유지한다. 암호화 PDF는 열지 않는다.

CBZ는 `..`, 절대 경로, 암호화 항목, 과도한 압축률, 80MB 초과 항목, 4GB 초과 총량, 5000페이지, 긴 변 20000 또는 4000만 픽셀을 거부한다. JPG/PNG/WebP만 받고 자연 정렬한다. 변환 EPUB에는 그 바이트를 무압축 ZIP 항목으로 넣는다.

만화는 페이지 이미지를 연 뒤 닫는다. 말풍선은 가장자리와 닿지 않는 밝은 영역의 휴리스틱이다. OCR은 Tesseract, RapidOCR, EasyOCR 중 설치된 것만 호출한다. 없으면 작업을 실패시키고 가짜 대사를 만들지 않는다. 번역은 기존 엔진이다. 배경 복원은 평탄한 색의 어두운 획만 칠하거나, 복잡하면 단색 플레이트다. 생성형 인페인트가 아니다. 한국어는 고정 레이아웃 HTML 오버레이로 올린다. 낮은 신뢰도, 빈 OCR, 가장자리 배치는 검토 플래그다.

편집기는 원본 이미지와 작업 이미지를 나란히 두고 OCR, 번역, 글꼴, 크기, 위치를 저장한 뒤 EPUB만 다시 만든다. 저장만으로는 API를 부르지 않는다. 「이 대사만 재번역」만 해당 블록을 기존 엔진으로 다시 보낸다.

페이지 병렬은 1–4다. 실패한 페이지만 다시 추출한다. 이미 끝난 페이지의 시도 횟수는 올라가지 않는다.

권리 확인은 UI 체크와 서버/CLI의 `rights_ack`다. PDF, CBZ, 만화는 이게 없으면 작업을 만들지 않는다. 소설 API는 기존 클라이언트가 그대로 동작하도록 이 필드를 필수로 두지 않았고, 화면에서는 시작 전에 체크를 요구한다.

## 3. 데이터베이스

`jobs`에 `mode`, `input_kind` 컬럼을 추가한다. 기본값은 `epub`이다. `pages`, `regions`, `schema_migrations` 테이블을 만든다. 기존 행을 지우거나 설정 파일을 다시 쓰지 않는다.

`tests/test_migration.py`가 옛 스키마에 작업, 용어집 `塔野 → 토노`, 이벤트를 넣고 `secrets.json` 바이트를 기록한 뒤 `DB()`와 `JobManager`를 열었다. 옛 제목, 용어집, 로그가 남았고 비밀 파일 바이트는 같았다. 그 위에 샘플 EPUB 작업을 새로 만들어도 옛 작업이 남아 있었다.

## 4. 실제로 실행한 테스트

환경: Linux, Python 3.12.3. 명령:

```bash
python3 -m pytest -q --tb=line
```

결과: **50 passed, 1 warning, 59.42s** (2026-11-06). 경고는 Starlette TestClient의 httpx deprecation이며 실패가 아니다.

이전 26개(파싱, 검증, EPUB2/3 목 번역, 장애 주입, 캐시 이어하기, 일시정지/취소/재개, 할당량, 웹 플로)가 포함되어 통과했다. `python -m epub_translator translate … --src-lang en --engine mock`도 `tests/test_image_api.py::test_cli_translate_src_lang_en`에서 종료 코드 0이었다.

추가로 통과한 것:

- PDF JPEG 3페이지가 EPUB 안에서 바이트 동일, RTL, 와이드 페이지 스프레드, 원본 PDF 해시 불변
- CBZ 자연 정렬, PNG/JPEG/WebP, LTR 옵션
- 텍스트 PDF 300 DPI 렌더(PyMuPDF, 약 300×300). 렌더러를 막으면 이미지 페이지만 성공하고 텍스트 페이지는 실패 표시와 함께 순서를 유지
- 암호화 PDF 거부, 경로 탈출, 픽셀 폭탄 헤더, zip bomb 비율 거부
- 실패한 페이지만 재시도(시도 횟수 1 → 2, 나머지 페이지는 1 유지)
- CBZ 변환 일시정지 중 진행이 멈추고, 취소 후 재개하면 6페이지가 완료
- 만화 fixture OCR(실제 인식 아님)로 용어집 `塔野 → 토노`, 오른쪽 대사 우선, 낮은 신뢰도 검토, 편집 저장 후 API 호출 수가 늘지 않음, 재번역 1회만 API 호출 증가, 원본 PNG 해시 유지
- Tesseract 5.3.4 + `jpn` / `jpn_vert`로 합성 이미지 `こんにちは` 가로·세로 모두 정확히 인식. 이 경로는 fixture와 별개다
- GPU 탐지 함수는 예외 없이 `cpu`를 반환(이 머신에 CUDA 공급자 없음)
- 300페이지 CBZ: 병렬 상한 2 이하, 300장 바이트 동일, 구조 검사 통과, EPUBCheck 통과, 원본 ZIP 불변
- 300페이지 PDF: 임베디드 JPEG 바이트 동일, 병렬 상한 2 이하. 이 케이스만 EPUBCheck는 끄고 돌렸다(`run_epubcheck=False`)
- 웹 API: 단독 PDF 변환은 받지 않음. PDF 만화 번역과 CBZ 만화 편집기 저장·재빌드는 됨

EPUBCheck 5.1.0과 시스템 Java로 소설 출력, PDF/CBZ 출력, 만화 출력, 300페이지 CBZ를 검사했다. `tools/epubcheck/`는 `.gitignore`라 저장소에 넣지 않았다. jar만 복사하면 `lib/`가 없어 기동이 실패하므로 jar와 `lib/`를 같이 두어야 한다.

## 5. 실행 방법

Windows는 `start.bat` 더블클릭. macOS/Linux는 `start.sh` 또는

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m epub_translator serve --host 127.0.0.1 --port 8000
```

PDF 렌더와 OCR은 `docs/OPTIONAL_DEPS.md`. 소설만 쓸 때는 설치하지 않아도 된다.

```bash
python -m epub_translator translate 책.epub --engine gemini --src-lang ja
python -m epub_translator translate 책.cbz --mode cbz --rights-ack
python -m epub_translator translate 책.cbz --mode comic --engine mock --rights-ack
python -m epub_translator translate 책.pdf --mode comic --engine mock --rights-ack
```

화면에서 EPUB은 소설, CBZ는 변환이다. PDF는 만화 번역을 켜야 하고, 켜기 전에는 작업을 만들지 않는다. 권리 확인을 체크해야 분석이 된다. 진행, 일시정지, 재개, 취소, 다운로드, 보고서는 소설과 같은 버튼이다. 완료된 옛 PDF 변환은 목록에서 받을 수 있지만 재개되지 않는다.

2026-11-08 확인: `python3 -m pytest -q --tb=line` → **56 passed**, 1 warning, 61.12s. EPUBCheck는 소설·CBZ·만화·샘플 서체 EPUB에서 통과했다. 300페이지 PDF는 변환 모드가 아니라 만화 모드(fixture OCR, API 호출 0)로 추출만 확인했다.

## 6. 한계 — 하지 않은 것

- 이 환경은 Linux다. Windows 더블클릭과 GPU 실기는 실행하지 않았다. `gpu_info()`는 CPU만 보고했다.
- RapidOCR, EasyOCR 패키지는 설치하지 않았다. 호출 코드는 있지만 이번 테스트가 그 경로를 실행하지 않았다. 실제로 돈 OCR은 Tesseract뿐이다.
- OpenAI, Gemini, Anthropic 유료 호출은 하지 않았다. 번역 테스트는 Mock 엔진이다.
- 말풍선 검출은 외곽선으로 닫힌 밝은 영역만 찾는다. 효과선, 반투명, 겹친 말풍선은 빠지거나 합쳐질 수 있다.
- 배경 복원은 생성형 인페인트가 아니다. 무늬와 그라데이션은 복원되지 않고 단색 플레이트와 검토 표시로 남는다.
- 글자 크기는 영역 크기 기준 추정이다. 편집기에서 고친다.
- WebP 바이트는 유지하지만 EPUB 핵심 미디어 타입이 아니라 EPUBCheck가 경고할 수 있다. 이번 WebP 샘플은 검사 대상에 넣었고 해당 테스트는 통과했다.
- 암호화 PDF/ZIP, DRM EPUB은 거부한다. 우회하지 않는다.

UI 초기 화면(파일 미선택, 소설 모드) 스크린샷: `docs/ui-home.png`. 파일 선택 뒤의 만화 편집기 화면은 브라우저 자동화로 파일을 집어넣지 못해 스크린샷은 없고, 편집기 API·EPUB 재생성은 테스트로 확인했다.
