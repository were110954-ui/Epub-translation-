# 만화 자동 번역 파이프라인 개선

기준 커밋은 이미 main에 합쳐진 `bedab4f`다. 이 문서는 그 위의 증분이다. 저작권이 있는 원고 페이지와 대사는 저장소와 이 문서에 넣지 않았다.

## 참조

당근망가번역기 공개 태그 **v3.8.5**, 커밋 `05da28e241ab87afbdb02f3115a6da8d44e6bd7a`.

- `package.json`의 `license`는 `GPL-3.0-only`이고 `LICENSE`는 GNU GPL 3이다.
- `README.md`는 흐름을 OCR → 번역 → 원문 제거 → 식자·검수 → 출력으로 적고, OCR은 HayaiOCR / HunyuanOCR / PaddleOCR, 원문 제거는 AOT / LaMa / Flux라고 적는다. 번역 엔진과 OCR·원문 제거는 따로 고른다.
- `src/main/bubbleLayout/detector.ts`의 `detectKoharuPageLayout`은 페이지 레이아웃 검출기다. `THIRD_PARTY_NOTICES.md`는 그 모델이 Apache-2.0 `ogkalu/comic-text-and-bubble-detector`의 RT-DETR ONNX이며, SHA-256을 확인한 뒤 내려받는다고 적는다.
- `src/main/textDetection/pageTextRegionDetector.ts`의 `detectPageTextRegions`는 그 검출기를 호출하는 어댑터다.
- `src/main/runtime/semantic-ocr/group-only-review-reading-order.cjs`는 세로 묶음을 오른쪽 열부터, 열 안에서는 위에서 아래로 정렬한다고 주석에 적는다.
- 같은 고지 파일은 LaMa / AOT / Flux 가중치와 GPL-3.0 `yolo12n_animetext`를 실행 중 내려받는 구성요소로 적고, 글꼴은 OFL-1.1 또는 Apache-2.0이라고 적는다.

소스와 릴리스 실행 파일, 모델, 글꼴은 복사하지 않았고 실행하지도 않았다. GPL 코드를 이 저장소에 넣으면 라이선스가 달라지므로, 공개 문서에 적힌 단계만 보고 이 앱의 CPU 경로에 맞게 따로 구현했다.

## 이 저장소에서 바꾼 것

| 파일 | 내용 |
| --- | --- |
| `epub_translator/text_lines.py` | 가로 한 줄·세로 한 열 검출. 칸 테두리는 빼고, 이웃 줄은 번역 묶음으로 묶음 |
| `epub_translator/ocr.py` | 그 줄 단위로 OCR. 가로/세로 재시도, 검토 플래그 |
| `epub_translator/inpaint.py` | 확신 있는 줄의 획만 마스크로 지움. 불확실하면 픽셀을 유지 |
| `epub_translator/fxl.py` | 한국어 줄바꿈과 넘침 판정. 페이지 XHTML은 줄을 `<br/>`로 둠 |
| `epub_translator/image_jobs.py` | 식자 넘침을 `typeset-overflow`와 검토로 저장. 보고서의 복원 표기 수정 |
| `epub_translator/server.py` | `GET /api/ocr-status` |
| `epub_translator/static/index.html` | 설치된 OCR 백엔드를 화면에 표시 |
| `tests/test_comic.py` | 복원 방식 이름을 `text-mask`로 맞춤 |
| `tests/test_manga_detect.py` | 합성 이미지만 쓰는 자동 경로 테스트 |
| `README.md`, `docs/OPTIONAL_DEPS.md` | 검출 모델을 넣지 않는다는 안내 |
| `epub_translator/hq.py` | 선택적 고품질. 페이지 이미지와 OCR·용어집·인물 정보를 선택한 모델에 보내고, 좌표를 검사한 뒤 식자 측정과 이미지 의견을 나눔 |
| `epub_translator/engines.py` | OpenAI·Anthropic·Gemini·호환 서버의 문서화된 이미지 요청. 모델 이름만으로 이미지 지원을 단정하지 않음 |

소설 번역, 용어집, 작업 큐, 편집기, DB는 그대로다. PDF를 EPUB으로만 바꾸는 모드는 되돌리지 않았다.

## 라이선스와 설치

- 앱 코드는 기존 저장소 라이선스를 따른다. 당근망가번역기 코드·모델·글꼴은 포함하지 않는다.
- 필수 패키지는 그대로다. Tesseract `jpn`과 `jpn_vert`는 선택이다. RapidOCR와 EasyOCR도 선택이고 GPU 휠을 강제하지 않는다.
- 검출용 ONNX나 생성형 인페인트 가중치는 내려받지 않는다.

## 합성 테스트에서 관측한 것

줄 검출을 넣은 뒤 `python3 -m pytest -q --tb=line`는 60건이었다. 고품질 계약을 더한 지금은 72건 통과, 1건 Starlette deprecation 경고다. EPUBCheck 5.1.0 jar가 있어 기존 EPUBCheck 단언도 같이 통과했다. 번역 API는 호출하지 않았고, 고품질 테스트의 네트워크는 mock이다.

합성 이미지에서 확인한 동작:

- 세로로 긴 상자 두 개는 오른쪽(x=70)이 왼쪽(x=12)보다 먼저 온다. 아래쪽 가로 상자는 그 다음이다.
- 세로 글자 열 두 개는 각각 얇은 상자이고 오른쪽이 먼저이며 같은 번역 묶음이다. 칸 테두리만 있는 페이지는 글자 줄이 없다.
- 24×24 영역에 한글 40음절은 넘침이고 글자 크기는 8이다. 180×80의 짧은 문장은 넘치지 않는다.
- 평탄한 흰 배경의 검은 획은 `text-mask`로 지워져 샘플 픽셀이 200을 넘고, 디스크의 원본 PNG 바이트는 그대로다.
- 확신 없는 획은 지우지 않는다. 칸 전체를 단색으로 덮는 flat-plate는 쓰지 않는다.
- 획이 없는 흰 타원 3개는 그대로 3개다. 가로/세로 Tesseract 합성 인식 테스트도 통과했다.

## 고품질 모드

기본 모드는 이미지를 보내지 않습니다. 고품질은 화면 또는 `--manga-hq --image-input-ack`로 켜고, 이미 고른 엔진·모델·키만 사용합니다. 페이지당 호출은 번역 1회, 식자가 상자를 넘칠 때만 교정 1회, 이미지 의견 1회까지입니다. 이미지는 긴 변 1024, JPEG 품질 70, OpenAI 계열은 `detail=low`입니다. 재시도는 호출당 2회이고 고품질 동시성은 1입니다. 단계마다 캐시하므로 이어하기와 편집 후 다시 내보내기는 그 단계를 다시 사지 않습니다. 대사를 고치면 그 페이지의 이미지 의견만 오래된 것으로 지웁니다.

응답에서 모르는 영역 id, 칸만 한 상자, 페이지 밖 좌표는 버립니다. 제안 상자는 검토로 저장하고 지우지 않습니다. 용어집에 없는 이름이나 말장난은 `name-uncertain` / `pun-uncertain`입니다. 식자 측정(넘침, 겹침, 마스크 밖 픽셀)과 모델의 이미지 의견은 서로 다른 기록이고, 의견은 정확성 증명이 아닙니다. `high_quality_verified`는 항상 거짓입니다.

## 검증에서 제외한 것

유료 번역 API 키는 이 환경에 없다. 그래서 실제 페이지 이미지를 모델에 보내 번역하고 식자한 뒤 다시 이미지를 검수하는 경로는 실행하지 않았다. `high_quality_verified`는 항상 거짓이고, 오프라인 계약 테스트는 고품질 성공이 아니다. 목 번역은 목 번역이다. 사람이 영역을 잡아 식자한 예시는 이 파이프라인의 결과가 아니다.

이 작업 환경에는 비공개 평가용 원고 파일(`/workspace/input/manga-sample.png`)이 없었다. 그래서 그 페이지의 자동 검출·OCR·복원 수치와 파생 이미지는 만들지 않았다. 대사 원문과 결과 이미지는 커밋하지 않는다.
