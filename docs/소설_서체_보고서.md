# 소설 EPUB 기본 서체 수정

번역 앱이 만드는 소설 EPUB의 기본 글꼴·자간·줄간격·문단 간격을 한국어 소설에 맞게 바꿨다. 특정 책만 손으로 고친 것이 아니다. 만화 고정 레이아웃, 입력 파일, DRM 거부, 엔진 설정, 기존 DB는 그대로다. 스크린샷의 서점 앱과 픽셀이 같다고 말하지 않는다. RIDI iOS에서는 확인하지 않았다.

## 원인

리더에서 글꼴·간격을 ‘원본’으로 두면 책 CSS가 보인다. 이전 기본값은 두 군데에서 어긋났다.

1. 글꼴 목록이 `Apple SD Gothic Neo`, `Malgun Gothic`을 `serif`보다 앞에 두었다. 명조 이름이 기기에 없으면 iOS/Windows는 설치된 고딕을 고른다.
2. 클래스 규칙(`p.body` 등)은 나중에 붙인 `p { }`보다 세다. 그래서 원문 스타일시트의 큰 `line-height`, `margin-bottom`, `letter-spacing`, `font-size: 16px`, `::first-letter` 굵기가 남았다. `.kt-leadin::first-letter { font-weight: bold }`와 드롭캡 `span`도 첫 글자(예: 굵은 ‘더’)를 만들 수 있다.

그래서 원문 CSS 선언을 규칙 안에서 바꾸고, 그다음 `kt-ko-readability.css`를 `<head>` 맨 끝에 둔다. `!important`는 쓰지 않고, 본문 글자 크기는 `1em`/`100%`만 써서 리더의 크기·간격 조절을 막지 않는다.

## 적용되는 기본값

| 항목 | 값 |
| --- | --- |
| 글꼴 | `"Nanum Myeongjo", "NanumMyeongjo", "Noto Serif KR", "Noto Serif CJK KR", "KoPubWorld Batang", "KoPub Batang", "RIDIBatang", "Batang", "BatangChe", serif` |
| 글자 크기 | `html` 100%, 본문 `1em`. px/pt는 `1em`으로 바꾼다. 제목의 em 크기는 유지하고, 제목의 px만 `1.4em` |
| 자간·단어 간격 | `normal` |
| 줄간격 | 본문 `1.65`(단위 없는 배수). 제목 `1.35` 근처는 유지 |
| 문단 | `margin: 0`, `padding` 위아래 0, `text-indent: 1em`, `text-align: left` |
| 정렬 | `justify`는 `left` |
| 한국어 줄바꿈 | `word-break: keep-all` |
| 첫 글자 | `::first-letter`의 굵기·확대·float를 해제. 짧은 드롭캡 `span`/`b`는 푼다 |
| 강조 | `em`/`i` 이탤릭, `strong`/`b` 굵기는 유지 |
| 제목 | 굵게, 들여쓰기 없음, 위 `1.4em` 아래 `0.6em` |
| 장면 구분·가운데 문단 | 들여쓰기 0, 가운데, 위아래 `1em` |
| 삽화 | 크기 규칙을 서체 규칙으로 덮지 않음 |
| 글꼴 파일 | 넣지 않음. 리더나 기기의 명조/serif에 맡긴다 |
| 언어 | 번역 결과는 `dc:language`와 `xml:lang`이 `ko` |

앞의 전각 공백은 CSS 들여쓰기와 겹치지 않게 문단 앞에서만 한 번 뺀다.

새 번역과, 캐시된 작업을 다시 마감할 때(`finalize`) 같은 규칙을 쓴다. API를 다시 부르지 않는다. 이미 뽑아 둔 소설 파일은 `python -m epub_translator restyle 책.epub -o 책.restyle.epub`. 고정 레이아웃은 이 명령이 거부한다.

## 바꾼 파일

- `epub_translator/rebuild.py` — 서체 재작성, 드롭캡 정리, `restyle_epub`
- `epub_translator/cli.py` — `restyle` 하위 명령
- `tests/test_parsing.py` — 줄간격 기대값 1.65
- `tests/test_typography.py` — 영문 CSS, 인라인 드롭캡, 강조, 언어, 스타일시트 순서, 일본어 샘플 재마감, 고정 레이아웃 거부
- `README.md`
- `samples/ko_typography_sample.epub` — 직접 쓴 짧은 한국어. EPUBCheck 5.1.0 fatal 0, errors 0, warnings 0
- `docs/novel-type-before.png`, `docs/novel-type-after.png`

PDF/CBZ/만화 모듈과 DB 스키마는 수정하지 않았다.

## 테스트

```bash
python3 -m pytest -q --tb=line
```

결과: **55 passed**, 1 warning(기존 TestClient deprecation), 59.84s. 소설 회귀, 만화, PDF, 300페이지, 이어하기가 포함된다.

EPUBCheck를 이 샘플에 따로 실행했다. `run_epubcheck("samples/ko_typography_sample.epub")` → version 5.1.0, fatal 0, errors 0, warnings 0.

스크린샷은 Chrome headless, 폭 390px, 같은 자작 문장이다. 이전 화면은 예전 기본값(고딕 폴백, 줄간격 1.8, 문단 아래 여백, 첫 글자 굵게)이고, 이후 화면은 코드의 `KO_CSS`다. 이 환경에 나눔명조가 있어 이후 화면은 명조로 보인다. 서점 앱 캡처가 아니며, 본문 여백은 스크린샷 프레임용이다. EPUB 본문 margin은 0이고 페이지 여백은 리더가 넣는다.

## 확인하지 못한 것

RIDI iOS(글꼴 원본, 크기 6, 줄/문단 간격 원본, 문단 너비 3)에서 다시 열어 보지 않았다. 리더가 ‘원본’일 때 이 기본값을 쓰지만, 앱이 자체 명조로 한 번 더 바꿀 수 있다. 기기 글꼴 이름이 스택과 다르면 마지막 `serif`로 떨어진다. 정확한 상용 서체 이름과 수치는 스크린샷만으로 알 수 없다.
